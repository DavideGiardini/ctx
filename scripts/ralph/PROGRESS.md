## 2026-07-26 — task 1: search backend seam + litellm `search` adapter

**What shipped.** New `ctx/core/search.py`: frozen `SearchHit`, `SearchError`, the
`SearchBackend` Protocol (`async search(query) -> list[SearchHit]` for now; task 2
adds `fetch`), `LiteLLMSearch` over `litellm.asearch`, the canned `TestSearch`
double, and `search_available()`. Plus the `"search"` config section
(`provider`/`max_results`/`max_tool_calls`) with the same re-merge treatment the
other sections get in `get_config()`.

**Tests.** Code-blind `test-spec-author` run produced `tests/specs/search.md`
(C1–C8) and `tests/test_search.py`. I pruned its C4 test (empty result set → `[]`)
as a shallow duplicate of C2's mapping path — recorded as a `Status:` line under C4
in the spec rather than silently dropped. Six tests remain, one per acceptance
clause plus the provider-reaches-the-backend check. Two test-infra fixes, neither
touching a contract: the local exception double was renamed `…Error` for ruff N818,
and `TestSearch` is imported `as CannedSearch` because pytest tries to collect any
module-level `Test*` class in a test module and warns on the constructor (this is
why `TestProvider` never warns — it is only imported in `conftest.py`, which is not
collected. Task 8 puts the search double in `conftest.py`, so the alias is only
needed in `tests/test_search.py`).

**One existing test deliberately changed.** `tests/test_config.py::test_c3_baseline_shape`
pinned the exact top-level key set of the defaults, so a new section makes it fail
by construction. Widened it to include `"search"` and amended `tests/specs/config.md`
C3 (which had already drifted — it did not mention `"import"` either) with an
explicit amendment note pointing the search-section contract at `specs/search.md` C8.

**Key decision — how `search_available()` knows which env var.** litellm does *not*
expose a provider→key-name mapping we can query: `ProviderConfigManager.get_provider_search_config()`
eagerly imports all thirteen backend configs and **blows up in this venv**
(`litellm.llms.brave.search.transformation` needs `dateutil`, which we don't ship).
So `search.py` carries an explicit `_API_KEY_ENV` table (13 entries, harvested from
each backend's `get_secret_str("…")` call). A backend mapped to `None` needs no key
(duckduckgo); a provider name absent from the table reports unavailable, so a typo'd
config line quietly offers no tools instead of tools that always fail (D4).
**Gotcha for a future iteration:** do not "improve" this by calling into
`ProviderConfigManager` — it raises `ModuleNotFoundError` here.

**Verification.** `bash scripts/check.sh` green (679 passed). No `qa-tester` and no
rendering: pure core with no UI surface this iteration, per PRD notes and PROMPT.md
step 7.

## 2026-07-26 — task 2: `fetch(url)` on the search backend

**What shipped.** `uv add trafilatura httpx` (14 transitive packages, `uv.lock`
regenerated by uv — not hand-edited), then `async fetch(url) -> str` on all three
sides of the seam in `ctx/core/search.py`: the `SearchBackend` Protocol,
`LiteLLMSearch` (httpx GET → Trafilatura markdown extraction), and `TestSearch` (a
canned page, defaulting to the new `CANNED_PAGE` constant so task 8's harness can
just construct it). Every failure — transport error, non-2xx, unparseable page,
empty extraction — surfaces as `SearchError`; no `httpx` type escapes. The page is
returned whole, never truncated (D10) — the window guard is task 7's.

**Three technical decisions worth not re-deriving.**

1. **How tests fake the network.** `LiteLLMSearch.__init__` takes an optional
   `transport: httpx.AsyncBaseTransport | None` that it hands to its internal
   `AsyncClient`, so tests pass `httpx.MockTransport(handler)`. That is httpx's own
   injection seam rather than an abstraction of ours, and it keeps `httpx` confined
   to the module that already owns the network. Nothing in `ctx` passes it.

2. **`favor_precision=True` on `trafilatura.extract` is load-bearing, not a taste
   call.** Without it, Trafilatura's fallback pass "rescues" a content-free
   client-rendered app shell as its nav labels — measured: 11 chars of
   `"Home\nLog in"` — which would reach the model as a *successful* fetch of
   nothing. With it, that page extracts to `None` (→ `SearchError`) while a real
   article body is byte-identical (1625 chars both ways). There is an `AIDEV-NOTE`
   on it. The empty-extraction `raise` sits **outside** the `try`, because the
   `except Exception` above would otherwise catch it and re-chain it as its own
   `__cause__` (the contract pins `__cause__ is None` there — it is our judgement
   call, not a swallowed library error).

3. **An explicit User-Agent.** httpx's default UA is refused outright by a good
   share of publishers, so `fetch` sends
   `"Mozilla/5.0 (compatible; ctx conversation IDE)"`. Not in the task text; without
   it a large fraction of real fetches would be a `SearchError` for no real reason.

**Tests.** Code-blind `test-spec-author` run, given only the new signatures +
docstrings and a prose intent statement, with an explicit budget of "3 tests, 4 at
most, ~50 lines of product code". It returned `tests/specs/search.md` C9–C13 and
three tests, all kept (each pins a distinct acceptance clause: uncapped body +
boilerplate stripped + redirect followed + timeout bound; transport error and 404
both → `SearchError`; empty extraction → `SearchError`). Nothing pruned this time —
C10 and C13 ride along inside C9's test rather than duplicating the page fixture,
which is exactly the shape the deletion test wants. **Its Write calls were denied**
(it has no read tools by design, and Write requires a prior read), so it returned
the file bodies in its report and I persisted them verbatim. Red was clean —
3 failed on `NotImplementedError`, 6 existing passed, no collection errors.

**Gotcha for a future iteration.** The subagent flagged one assumption I confirmed
rather than changed: C13 asserts `request.extensions["timeout"]["read"] ==
FETCH_TIMEOUT_SECONDS`. That holds because the single float is passed as the
client's whole timeout, so httpx expands it to all four components. If anyone later
wants a split budget (short connect, long read), C13 has to be restated first.
